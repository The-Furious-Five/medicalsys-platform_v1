# Seccion 11 Evaluacion OWASP Top 10

La revision de codigo identifico cuatro areas que requieren evidencia de ejecucion. Los escenarios “antes” describen el comportamiento observable en la configuracion/codigo previo; no implican que se haya realizado una prueba de penetracion en vivo en esta sesion.

| Categoria | Problema y explotacion anterior | Correccion aplicada | Evidencia posterior y estado |
|---|---|---|---|
| A01 Broken Access Control | Compose publicaba directamente los puertos de los servicios. Un cliente local podia intentar `curl http://localhost:8088/api/v1/...` y enviar `X-Roles` manipuladas. El gateway derivaba los headers de roles del JWT, pero la ruta directa evitaba esa frontera. | Se quitaron los `ports` de los servicios y dependencias de datos; solo gateway publica puerto. Compose define red `medicalsys-interna`. | Prueba local: gateway respondió HTTP 200 en 8080 y el acceso directo a `localhost:8088` no fue alcanzable. Compose publica únicamente `ms-gateway:8080`. La ruta de negocio vía gateway sigue pendiente porque Aiven impide iniciar los microservicios. |
| A07 Identification and Authentication Failures | Los servicios validaban firma/expiración del JWT sin consultar el `jti` de Redis que identidad elimina al cerrar sesión. Un token revocado podía continuar siendo aceptado hasta expirar. | Gateway consulta `identity:session:{jti}` en Redis para cada JWT y responde 401 si no hay sesión activa; error de Redis falla cerrado con 503. | La prueba unitaria del filtro confirma 401 para una sesión ausente. Falta el recorrido integrado login/logout con el mismo token hacia pacientes e historial: el `.env` apunta al host de ejemplo de Aiven y esos servicios no arrancan. |
| A05 Security Misconfiguration | `GATEWAY_ALLOWED_ORIGINS` permitía `*`, usuarios demo estaban habilitados por defecto y Actuator exponía detalles de salud. Además, servicios y datos estaban publicados en host. | CORS usa orígenes exactos (por defecto `http://localhost:4200`), usuarios demo desactivados y Actuator configurado `when-authorized`; puertos cerrados. | Prueba de preflight: origen permitido recibió `Access-Control-Allow-Origin: http://localhost:4200`; origen `https://malicioso.example` recibió 403. Puertos confirmados; smoke test completo pendiente por el fallo de base de datos en Aiven. |
| A08 Software and Data Integrity Failures | El webhook omitía la validación HMAC cuando `WHATSAPP_APP_SECRET` estaba vacío, por lo que aceptaba payloads sin firma. | Proveedor `meta` falla al arrancar sin secreto y todos los payloads exigen firma HMAC-SHA256 válida; sin secreto de cualquier proveedor, el webhook responde 401. | Las 16 pruebas unitarias del servicio cubren firma ausente, inválida, válida y secreto ausente. La prueba HTTP integrada del webhook sigue pendiente porque `ms-notificaciones` no puede completar Flyway sin conexión a Aiven. |

Los controles de integridad SHA-256 de documentos ya forman parte de `ms-documental`; su alcance y pruebas deben anexarse con evidencia de ejecucion antes de afirmar cobertura integral de A08.
